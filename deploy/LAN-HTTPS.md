# HTTPS внутри приватной сети (ZeroTier / Tailscale / LAN)

## Зачем это вообще нужно

Браузеры отдают микрофон, камеру и демонстрацию экрана только в **secure
context**. Единственное исключение из правила — `localhost`. Всё остальное,
включая адреса приватных сетей вроде `10.150.20.1`, считается небезопасным
origin'ом: `getUserMedia()` и `getDisplayMedia()` там просто отклоняются, и
никакими настройками сервера это не обходится.

Практически это значит: по `http://10.150.20.1:3001` OwnCord откроется,
чат будет работать, а **звонки — нет**. Плюс не заработают service worker
(push-уведомления) и установка PWA.

Публичный центр сертификации (Let's Encrypt и любой другой) сертификат на
приватный IP не выдаст — такие адреса не принадлежат никому глобально.
Поэтому нужен **свой локальный CA**. Именно это делает `mkcert`.

---

## Настройка сервера (один раз)

### 1. Поставить mkcert и завести локальный CA

```bash
brew install mkcert nss
```

```bash
mkcert -install
```

Вторая команда спросит пароль: она добавляет корневой сертификат mkcert в
системное хранилище доверия macOS. `nss` нужен, чтобы CA подхватил ещё и
Firefox — он держит собственное хранилище, отдельно от системного.

> **Что это значит с точки зрения безопасности.** В системе появляется CA,
> которым можно подписать сертификат для любого домена, и этот компьютер
> ему поверит. Приватный ключ CA лежит локально в `$(mkcert -CAROOT)`.
> Пока ключ не утёк — риска нет; если утёк, злоумышленник сможет
> убедительно подделывать HTTPS-сайты для устройств, где установлен этот
> CA. Не копируй `rootCA-key.pem` никуда. Удалить CA можно в любой момент:
> `mkcert -uninstall`.

### 2. Выпустить сертификат на адрес сервера

```bash
cd server && mkdir -p certs && cd certs && mkcert 10.150.20.1 localhost 127.0.0.1 ::1
```

Подставь свой ZeroTier-адрес вместо `10.150.20.1` — посмотреть его можно
через `zerotier-cli listnetworks` или `ifconfig`. Сертификат действует
чуть больше трёх лет.

### 3. Прописать пути в `server/.env`

```
PORT=3001
HOST=0.0.0.0
JWT_SECRET=<длинная случайная строка>
TLS_CERT_FILE=./certs/10.150.20.1+3.pem
TLS_KEY_FILE=./certs/10.150.20.1+3-key.pem
```

Секрет генерируется так:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Когда обе переменные `TLS_*` заданы, сервер поднимает HTTPS сам, без
nginx. Если файл сертификата не читается — процесс падает на старте с
явной ошибкой, а не откатывается молча на HTTP: иначе легко получить
«TLS вроде включён, а микрофон почему-то не работает».

### 4. Запустить

```bash
npm run build && npm start
```

Сервер отдаёт и API, и собранный фронт на одном порту:
`https://10.150.20.1:3001`.

Приватный ключ и папка `certs/` закрыты в `.gitignore` — в репозиторий они
не попадут.

## Подключение остальных участников

Каждому устройству нужно доверять твоему CA — иначе оно увидит
предупреждение о сертификате, а звонки всё равно не заработают (Chrome
отказывается регистрировать service worker на странице с невалидным
сертификатом, а происхождение помечает как небезопасное).

### 1. Забрать корневой сертификат

На сервере:

```bash
open "$(mkcert -CAROOT)"
```

Кавычки здесь обязательны: на macOS путь по умолчанию —
`~/Library/Application Support/mkcert`, и без них пробел в
«Application Support» разобьёт аргумент на два, а `open` отругается,
что таких файлов нет.

Нужен файл **`rootCA.pem`**. Только он. Файл `rootCA-key.pem` — приватный
ключ центра сертификации, его передавать нельзя никому и никогда.

Отправь `rootCA.pem` участникам любым способом.

### 2. Установить его на устройстве

**macOS.** Двойной клик по `rootCA.pem` → откроется «Связка ключей» →
найти сертификат `mkcert <имя>@<машина>` → двойной клик → раздел
«Доверие» → «При использовании этого сертификата» = **«Всегда доверять»**.

**Windows.** Здесь два места, где обычно всё и ломается: расширение
`.pem` и выбор хранилища. Разберём оба.

*Подвох 1: переименуй файл.* Windows не умеет открывать `.pem` мастером
импорта — двойной клик либо ничего не сделает, либо предложит выбрать
программу. Переименуй `rootCA.pem` → **`rootCA.crt`**. Содержимое файла
менять не нужно, Windows смотрит только на расширение.

> Если расширения не видно, включи их: в Проводнике вкладка «Вид» →
> галочка «Расширения имён файлов». Иначе легко получить `rootCA.pem.crt`.

*Подвох 2: хранилище надо выбрать вручную.* Вариант «Автоматически
выбрать хранилище на основе типа сертификата» кладёт корневой сертификат
в «Промежуточные центры сертификации», где он **не даёт доверия**.
Это самая частая причина «я всё установил, а замок всё равно
перечёркнут».

Дальше по шагам:

1. Двойной клик по `rootCA.crt` → **«Установить сертификат»**.
2. Расположение хранилища:
   - **«Текущий пользователь»** — проще, прав администратора не требует,
     работает для твоей учётки. В большинстве случаев этого достаточно.
   - **«Локальный компьютер»** — для всех пользователей ПК, потребует
     подтверждения UAC.
3. Выбрать **«Поместить все сертификаты в следующее хранилище»** →
   «Обзор» → **«Доверенные корневые центры сертификации»** → «ОК».
4. «Далее» → «Готово».
5. Windows покажет «Предупреждение системы безопасности» с текстом про
   то, что подлинность сертификата не подтверждена. Для своего CA это
   ожидаемо — **«Да»**.
6. **Перезапустить браузер полностью** (не просто закрыть вкладку).
   Chrome и Edge читают системное хранилище при старте.

*Быстрый путь через PowerShell.* Если возиться с мастером не хочется —
открыть PowerShell **от имени администратора** и выполнить:

```powershell
Import-Certificate -FilePath C:\путь\к\rootCA.crt -CertStoreLocation Cert:\LocalMachine\Root
```

Без прав администратора — то же самое, но только для своей учётной
записи (работает так же, UAC не нужен):

```powershell
Import-Certificate -FilePath C:\путь\к\rootCA.crt -CertStoreLocation Cert:\CurrentUser\Root
```

*Проверить, что сертификат встал куда надо:*

```powershell
Get-ChildItem Cert:\LocalMachine\Root, Cert:\CurrentUser\Root | Where-Object { $_.Subject -like "*mkcert*" }
```

Если вывод пустой — сертификат не в том хранилище, вернись к шагу 3.

*Удалить, если что-то пошло не так:* `certmgr.msc` → «Доверенные
корневые центры сертификации» → «Сертификаты» → найти запись `mkcert …`
→ удалить.

**Android.** Настройки → Безопасность → Шифрование и учётные данные →
«Установка сертификатов» → «Сертификат ЦС» → выбрать файл. Система
покажет предупреждение — для своего CA это ожидаемо.

**iOS.** Отправить файл на устройство и открыть → Настройки → «Профиль
загружен» → установить. Затем обязательный второй шаг, без которого
ничего не заработает: Настройки → Основные → Об этом устройстве →
«Доверие сертификатам» → включить тумблер напротив своего CA.

**Firefox** (на любой ОС) использует своё хранилище. Если на сервере был
установлен пакет `nss`, mkcert прописывает CA и туда автоматически. На
чужих машинах: `about:preferences#privacy` → «Сертификаты» → «Просмотр
сертификатов» → «Центры сертификации» → «Импортировать».

### 3. Открыть

`https://10.150.20.1:3001` — замок должен быть обычным, без
предупреждений. Если замок перечёркнут, CA установлен не до конца
(на iOS почти всегда забывают шаг с «Доверием сертификатам»).

## Быстрая проверка, что secure context на месте

Открыть консоль браузера на странице OwnCord:

```js
isSecureContext;                              // должно быть true
navigator.mediaDevices.getUserMedia !== undefined;  // должно быть true
```

Если первое `false` — сертификат не доверен, звонки не заработают.

---

## Запасной вариант без установки CA

Если на какое-то устройство CA поставить нельзя, конкретно Chrome можно
уговорить считать один origin доверенным:

`chrome://flags/#unsafely-treat-insecure-origin-as-secure` → вписать
`http://10.150.20.1:3001` → Enabled → перезапустить браузер.

Тогда микрофон отдаётся и по обычному HTTP. Это костыль на одно
устройство: настройка живёт в профиле браузера, не переносится, в Firefox
и Safari аналога нет, а service worker и PWA всё равно не поднимутся.
Для постоянной работы — только вариант с CA.

## Если появится свой домен

Тогда всё становится проще и чище: заводишь A-запись
`owncord.example.com → 10.150.20.1` (приватный IP в публичном DNS — это
нормально, так делают) и выпускаешь настоящий сертификат Let's Encrypt
через **DNS-01 challenge**. Он не требует, чтобы сервер был доступен из
интернета — подтверждение идёт TXT-записью в DNS.

Плюс в том, что сертификату верят все устройства из коробки: ничего
никому устанавливать не надо, телефоны и гости работают сразу. Минус —
нужен домен и DNS-провайдер с API для автоматического продления
(Cloudflare, например). Для группы больше нескольких человек этот путь
окупается быстро.
